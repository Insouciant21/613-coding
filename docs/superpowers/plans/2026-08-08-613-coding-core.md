# 613 Coding Core Feedback Loop Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `subagent-driven-development` (recommended) or `executing-plans` to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Implement the self-owned agent loop, objective feedback mechanism, governance ports, persistence, memory, providers, and offline mock demonstration.

**Architecture:** Pydantic domain models and Protocol ports isolate business rules from adapters. `AgentLoop` consumes a validated `LLMProvider` response, dispatches tool calls through `PolicyEngine`, runs validators, classifies objective feedback, persists events, and applies explicit stop conditions.

**Tech Stack:** Python 3.12+, `uv`, Pydantic, pytest, SQLite stdlib, LanceDB, HTTPX, `keyring`, Typer/FastAPI ports used by the delivery plan.

## Global Constraints

- Tests must run offline with fake LLMs, fake tools, deterministic embeddings, temporary repositories, and temporary databases.
- No high-level agent framework may provide the loop.
- No tool executes before schema validation and policy evaluation.
- `finish` requires fresh passing validation and no pending approval.
- Every state transition and task result is recorded in an event model.
- TDD is mandatory: red test, observed failure, minimal green implementation, refactor, focused verification, commit.
- Before each task commit, append actual task evidence to `AGENT_LOG.md` and `DELIVERY_STATUS.md`; after the commit, update `PLAN.md` with the hash.
